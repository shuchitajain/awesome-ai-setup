# Example: Flutter + Riverpod + Clean Architecture

**Reference output for Flutter projects using Riverpod and Clean Architecture.**

This example shows what high-quality AI context looks like for a specific, well-defined stack. It exists to answer: “If I run the generation agents on a Flutter Riverpod project, what should the output look like?”

---

## This Is an Example, Not a Template

The files in this example were written as if they were generated by the agents in `agents/` - applied to a hypothetical but realistic Flutter app (“TaskFlow”).

**Don't copy these files verbatim.** The folder names, class names, entity names, and conventions are specific to the TaskFlow example. Copying them to your project would give AI assistants context about the wrong codebase.

**Do use them as a quality reference.** After running the generation agents on your project, compare the output to these examples. Are the generated files this specific? This concrete? This free of generic advice? If not, the agents may need a second pass with more detail.

## How to Use This Example

### Option A - Generate for your own Flutter project (recommended)

```
# In your Flutter project, with your AI assistant:

"Read agents/generate-architecture.md and execute it on this repository."

# Compare the output to examples/flutter/ARCHITECTURE.md
# to calibrate the expected quality.
```

### Option B - Adapt directly (if your stack matches closely)

If your project is Flutter + Riverpod + Clean Architecture with feature-first organization, you can start from these files and adapt them. Replace:
- Folder names → your actual folder structure
- `TaskFlow`, `Task`, `Project`, `Workspace` → your actual domain entities
- All examples referencing TaskFlow → examples from your codebase
- `MEMORY.md` → delete all entries and start fresh (these decisions are TaskFlow's, not yours)

## Multi-Tool Setup

`AGENTS.md` at the project root is the canonical cross-tool agent context file, natively read by Cursor and GitHub Copilot for agent instructions. It works across any tool that follows the AGENTS.md convention.

For **Claude Code**, `CLAUDE.md` is the primary global context file. You can reference the scoped instruction files explicitly, or use `CLAUDE.md` as a standalone file that merges their key content.

For **GitHub Copilot**, `.github/copilot-instructions.md` handles repository-wide instructions and code review behavior. `AGENTS.md` covers agent instructions. Both can coexist.

The scoped `.github/instructions/*.instructions.md` files are read natively by GitHub Copilot and provide per-file-type conventions beyond what `AGENTS.md` covers.
